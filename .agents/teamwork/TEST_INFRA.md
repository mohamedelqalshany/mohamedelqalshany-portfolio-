## 1. Executive Summary & Design Principles

The Mohamed El-Qalshany portfolio test infrastructure is an **opaque-box, requirement-driven, zero-dependency end-to-end test suite** designed to rigorously validate the static build artifacts (`dist/`), runtime scripts, media catalog, typography, design tokens, and user journeys across all 26 features defined in `PROJECT.md` and `ORIGINAL_REQUEST.md`.

### Core Engineering Principles:
1. **Zero External Framework Overhead**: Built exclusively on native Node.js 22+ modules (`node:test`, `node:assert/strict`, `node:child_process`, `node:fs`, `node:path`, `node:url`). Requires zero third-party testing libraries (e.g. Jest, Mocha, Playwright, Vitest), ensuring instant startup (< 50ms), deterministic reproducibility, and zero supply chain vulnerabilities.
2. **True Opaque-Box SSG Validation**: Evaluates actual compiled HTML, CSS bundles, XML sitemaps, JSON-LD schemas, and physical media files in `dist/` generated by Astro 5 SSG, rather than mocked virtual component trees.
3. **Mathematical Correctness**: Features exact WCAG 2.2 mathematical contrast calculation ($L = 0.2126R + 0.7152G + 0.0722B$) and strict Schema.org Person metadata schema verification.
4. **Adversarial & Boundary Verification**: Includes extreme edge cases, HTML entity decoding, directional bidirectionality (`dir="rtl"` page with `dir="ltr"` phone inputs), and media concurrency singletons across audio and video players.
5. **Progressive 4-Tier Test Topology**:
   - **Tier 1 (Feature Coverage)**: Isolated happy-path testing across all 26 features (135 tests).
   - **Tier 2 (Boundary & Corner Cases)**: Edge conditions, extreme text sizes, empty cases, and formatting strictness (130 tests).
   - **Tier 3 (Cross-Feature Pairwise Interactions)**: Synergy across feature combinations (33 tests across 15 suites).
   - **Tier 4 (Real-World Visitor Scenarios)**: Complete end-to-end user journeys from arrival to conversion (26 tests across 5 scenarios).
   - **Total Suite**: 324 tests, 100% pass rate.

## 3. Helper Utility Specifications

### 3.1 `tests/helpers/wcag.js`
Implements the W3C WCAG 2.2 Relative Luminance and Contrast Ratio standard formulas:
- **Linearization**:
  $$\text{channelLinear} = \begin{cases} \frac{C_{\text{srgb}}}{12.92} & C_{\text{srgb}} \le 0.04045 \\ \left(\frac{C_{\text{srgb}} + 0.055}{1.055}\right)^{2.4} & C_{\text{srgb}} > 0.04045 \end{cases}$$
- **Relative Luminance ($L$)**:
  $$L = 0.2126 R_{\text{linear}} + 0.7152 G_{\text{linear}} + 0.0722 B_{\text{linear}}$$
- **Contrast Ratio ($CR$)**:
  $$CR = \frac{L_1 + 0.05}{L_2 + 0.05} \quad (\text{where } L_1 \ge L_2)$$
- Functions exported:
  - `parseHexColor(hex)`: Hex to `{r, g, b}` normalized.
  - `getRelativeLuminance(rgb)`: Exact relative luminance $[0.0, 1.0]$.
  - `getContrastRatio(fgHex, bgHex)`: Mathematical contrast ratio $[1.0, 21.0]$.
  - `isWcagAaCompliant(fgHex, bgHex, isLargeText)`: Validates threshold ($CR \ge 4.5:1$ for normal body text, $CR \ge 3.0:1$ for large text/headings).

### 3.2 `tests/helpers/dist-loader.js`
Provides deterministic, cached, and safe file loading for:
- All 6 SSG route targets:
  1. `/` -> `dist/index.html` (Arabic Gateway)
  2. `/en` -> `dist/en/index.html` (English Gateway)
  3. `/vo` -> `dist/vo/index.html` (Arabic VO Hub)
  4. `/en/vo` -> `dist/en/vo/index.html` (English VO Hub)
  5. `/marketing` -> `dist/marketing/index.html` (Arabic Marketing Hub)
  6. `/en/marketing` -> `dist/en/marketing/index.html` (English Marketing Hub)
- Design token and stylesheet files (`tokens.css`, `base.css`, `global.css`).
- Authoritative JSON catalogs (`site.json`, `samples.json`, `marketing.json`).
- Physical media files in `dist/media/` (measuring byte sizes and file extensions).
- XML sitemaps (`sitemap-index.xml`, `sitemap-0.xml`).

### 3.3 `tests/helpers/html-parser.js`
Custom non-destructive regex-based static HTML parser:
- `extractTagAttributes(html, tagName)`: Parses all occurrences of a tag into attribute dictionaries.
- `extractElementsByAttr(html, attrName, attrValue)`: Queries elements matching presence or specific attribute values.
- `extractElementsByTag(html, tagName)`: Extracts tag contents, attributes, and inner text.
- `extractMetaTags(html)`: Extracts named, OpenGraph, viewport, and charset metadata.
- `extractJsonLd(html)`: Safely extracts and JSON-parses `<script type="application/ld+json">` schemas.
- `extractLinks(html)`: Extracts anchor `<a>` links with `href`, `ariaLabel`, `rel`, `target`, and `class`.
- `stripTags(html)`: Strips HTML tags and normalizes whitespace for semantic text analysis.

### 3.4 `tests/helpers/schema-validator.js`
Validates JSON-LD metadata conformance to Schema.org `Person` specifications:
- Verified `@context` (`https://schema.org`).
- Verified `@type` (`Person`).
- Core profile: `name`, `url`, `jobTitle`, `email`, `telephone`.
- Address object: `@type: 'PostalAddress'`, `addressCountry: 'EG'`.
- Linguistic capability: `knowsLanguage: ['ar', 'en']`.

## 6. Maintenance & Extensibility Guide

When adding new media samples or expanding service packages:
1. **Catalog Updates**: Update `src/data/samples.json` or `src/data/marketing.json`.
2. **Build Generation**: Run `npm run build` to update `dist/`.
3. **Automated Verification**: Run `npm test`. The test suite automatically reads the updated catalogs and verifies physical file existence in `dist/media/`, sitemap links, and category distribution without manual test alterations.
